# 2026-11-22 网络工具箱 NetProbe（wifi-ios）

## 项目定位
Flutter 单工程出 Android + iOS 的 WiFi 分析仪 + 网络工具箱。工程根 `D:/WorkBuddy_ai/data/wifi-ios`，
包名 `com.gyq.netprobe`，应用名「网络工具箱」，Flutter 3.24.5 / Dart 3.5.4。

## 关键技术结论（★ 值得长期保留，避免重复研究）
- **iOS 扫描附近 WiFi 是死路**：Apple TN3111 明确无通用扫描 API；`NEHotspotNetwork.signalStrength`
  对普通 App 返回**占位值**（由 wifid 按调用方 entitlement 计算），改代码无用。
- **付费开发者证书救不了**：能勾的只有 `wifi-info`（只给当前 SSID/BSSID）；
  `HotspotHelper` 需 Apple 人工审批（后台无此项）；`com.apple.private.*` 只有 Apple 内部 profile 有。
  provisioning profile 里的 UDID 只决定"能否装到这台设备"，与 API 权限无关。
- **用户设备 iPhone 15 Pro Max / iOS 17.3 / A17 Pro 可以越狱**（2026-11 核实）：
  - Dopamine 3.0（2026-08 发布）支持 A12–A17 Pro + iOS 15.0–17.3.1
  - Relaxin 公测支持 iOS 16.5.1–17.3.1 + A15–A17 Pro（明确含 15 Pro Max）
  - TrollStore 只到 iOS 17.0（CoreTrust 漏洞 17.0.1 修复），用户 17.3 用不了
  - ★ 17.3.1 是天花板，升级即永久失去越狱机会
- 越狱后取真实扫描的正确做法：装 root helper 负责扫描 + 本地 socket 给 App，比注入 entitlement 稳。
- iOS 替代方案：ESP32-S3 做 BLE 探针（用户手上有板子）。

## 架构
- Dart：models / bridge(MethodChannel+EventChannel) / nettools(DoH DNS、端口扫描、网段发现、风险研判) / 4 个页面 / 自绘图表
- Android 原生（4 文件）：WifiBridge（扫描/当前连接/RSSI 轮询）、ProbeBridge（系统 ping/traceroute/ARP/音调）、
  ToneEngine（AudioTrack 合成音）、MainActivity（权限回调）
- iOS 原生：**全部代码合并到 `ios/Runner/AppDelegate.swift`**，因为新增 .swift 必须手动登记进
  project.pbxproj 才参与编译，Windows 上无法验证工程文件，合并进已注册文件规避风险。
- 信号音：Android AudioTrack / iOS AVAudioSourceNode 实时合成正弦脉冲，频率 280–1200Hz、
  音量随质量线性映射，不打包音频资源。

## 踩过的坑
- Kotlin `String.isNotEmpty` 是**函数**不是属性，写成 `ip.isNotEmpty` 编译报 "Function invocation expected"。
- Kotlin **表达式体函数（`= try { }`）里不能 return**，必须改 block body（`wlanMac()` 踩到）。
- 新增 iOS .swift 文件不登记 pbxproj = 不编译，且容易和已合并代码重复定义符号。
- adb over network：daemon 每次 Bash 调用会重启，**connect 必须和后续操作写进同一条命令**，需 `MSYS_NO_PATHCONV=1`。
- ScanResult.timestamp 是"开机以来的微秒"，算新鲜度要用 `SystemClock.elapsedRealtime()*1000` 做基准，
  不能和 `System.currentTimeMillis()` 混用。
- 无定位权限时 Android 返回 `<unknown ssid>`，**判断"已连接"不能依赖 SSID**，要看 IP 或 networkId。

## 实测验证（192.168.71.46:5555 设备）
WiFi 扫描出 1 个开放网络、局域网页扫出 6 台设备（含 iPhone 靠 62078 识别）、
设备详情端口扫描、Ping 4/4 收到 5–10ms、DoH 查 example.com 返回 2 个 A 记录 64ms——全部正常。
注：该设备/模拟器的 `scanResults.level` 返回 0，真机才有真实 dBm，已做 "—/无值" 降级显示。
